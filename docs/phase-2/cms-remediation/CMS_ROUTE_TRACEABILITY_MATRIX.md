# CMS Route Traceability Matrix

Every published public route, measured against production on 2026-09-04 after
the marketing-capability deployment. Nothing here is inherited from an earlier
document: each row is generated by `tools/route-matrix.php`, which walks the
live database, parses each object's stored content, and asks WordPress itself
whether each marketing role may edit and publish it.

**88 routes. 88 editable by both marketing roles. 88 publishable by Marketing
Publisher. 0 exclusions.**

## How to read the columns

| Column | Meaning |
|---|---|
| **Editor** | The editing surface WordPress actually serves for that post type. |
| **Sections / Cards** | `gemreserve/section` and `gemreserve/repeatable` blocks in the stored content — the things the client asked to add, remove, duplicate and reorder. |
| **Slots** | Individually editable typed fields inside the blocks (text, link, image, icon). |
| **Images** | Editable image slots plus populated hero/cut-out image fields. |
| **SEO** | Structured SEO fields on the edit screen: title, description, canonical, noindex. |
| **Mkt edit / publish** | `user_can()` answered by WordPress for `gr_marketing_editor` and `gr_marketing_publisher`. |

Preview (desktop/tablet/mobile) and revisions are properties of the block
editor and of `supports => revisions`, both of which every row below has; they
are verified once by browser test AT-08 and AT-11 rather than re-asserted per
route.

## The families that are not GemReserve blocks

The 58 migrated routes are the designed marketing pages, and they carry the
whole affordance set the client asked for. The other 30 are newer content, and
they were opened and tested rather than assumed compliant.

### 25 routes — Classic block, imported HTML

`/learn/`, the twelve Learn articles, and twelve gemstone-topic pages, all
authored by another party on 2026-09-02 and stored as raw HTML in
`post_content` with no block delimiters.

Gutenberg presents that as a **Classic block**: a visual rich-text editor, not
a code box. Browser test **AT-P3** opens one as a Marketing Publisher and
asserts the block editor is in use and the content renders in the canvas. A
marketing user edits the prose, links and headings there without seeing markup.

**They are deliberately not converted to blocks.** They are prose articles with
no designed sections and no card groups — there is nothing to reorder or
duplicate — so conversion would rewrite 25 pages of somebody else's live
content to gain an affordance the content has no use for. `CMS_MIGRATION_RUNBOOK.md`
covers the conversion if the client later wants it, and it is reversible; doing
it unasked is not.

### 3 routes — core Gutenberg blocks

`/privacy-policy/`, `/terms-of-use/`, `/cookie-policy/`. Already authored as
real core blocks (paragraphs, headings, lists), individually editable and
reorderable. Nothing to do.

### 2 routes — structured fields only

`/sapphire/` and `/diamond/`, newer gemstone records with an empty body. They
render 113 KB of templated page from the theme and their hero and SEO fields
are now editable — those fields were previously declared for `page` only, so a
gemstone's title tag could only be changed in the database. No per-page body
exists to edit, which is a content decision for the client, not a defect.

## Regenerating this

```bash
sudo -u www-data wp --path=/var/www/GemReserve/wordpress \
  eval-file wordpress/plugins/gemreserve-visual-cms/tools/route-matrix.php
```

It creates no state: where a marketing account does not exist it makes a
throw-away user to ask WordPress the access question, and deletes it before
returning. Production still holds exactly two accounts after a run.
