# GemReserve Phase 1 — Internal Implementation Plan

1. **Architecture:** Build a strict TypeScript Next.js App Router project with three route-level server components, shared layout/navigation/footer primitives, reusable section/card/diagram components, and typed content modules for every claim, metric, process step, and gemstone record.
2. **Design tokens:** Centralize the near-black, blue-black, ivory, muted gray, warm-gold, border-gold, and teal palette; editorial serif and neutral sans typography; restrained radii; precise rules; fluid spacing/type; focus rings; shadows; and motion timings in CSS custom properties.
3. **Navigation and footer:** Normalize the three mockups into one accessible sticky header, keyboard-capable desktop dropdowns, focus-managed mobile sheet, optional announcement bar, contextual breadcrumbs, implemented-route links, disabled future destinations, and a responsive multi-column footer.
4. **Brand assets:** Manually redraw the stable gold crest geometry and four-gem arrangement as SVG, add the `GR` monogram and horizontal `GemReserve.io / OWN. TRADE. REDEEM.` lockup, then render transparent high-resolution PNG and favicon/app-icon variants from those vectors.
5. **Photographic assets:** Use image-to-image generation from inspected mockup crops for the three heroes, secure vault, Swiss trust scene, gemstone/vault CTA imagery, and a consistent ten-stone catalog source; preserve text as HTML, inspect for malformed facets/tools/text, keep masters, and export optimized WebP/AVIF delivery files with an asset manifest.
6. **Page systems:** Compose Home from editorial hero, six trust pillars, eight-step process, six-asset preview, metric strip, waitlist CTA, and footer; How It Works from hero, nine-step timeline, six pillars, security/vault split, SVG lifecycle, Swiss CTA, and footer; Assets from hero/value rail, registry metrics, working filter/sort catalog, investment panel, waitlist CTA, and footer.
7. **Motion:** Implement lightweight CSS/IntersectionObserver reveals, one-time metric count-up, connector activation, hero depth, glints, dropdown/menu transitions, filter transitions, hover lift, and CTA shine using transform/opacity with complete reduced-motion fallbacks.
8. **Responsive adaptation:** Preserve split heroes at large widths; use stacked intentional crops and vertical connected timelines below tablet; use 5/3/2/1-column catalog breakpoints, scroll-safe filter controls, two-column metric groups, 44 px controls, and collapsed footer groups. Verify all eight required viewport sizes.
9. **QA:** Run formatter, ESLint, strict TypeScript, production build, and a local production server; exercise navigation, focus handling, waitlist validation/success, filters/sort, reduced motion, links, console/network state, and overflow; capture fresh 1440 px desktop and 390 px mobile screenshots for all routes plus a 768 px tablet checkpoint; compare and iterate against the source boards.
10. **Safe publication:** Keep raw mockups/reference crops, temporary generations, build output, and caches ignored; initialize `main` only because the verified remote is still empty; inspect all staged/unstaged files, stage only explicit project paths, commit once checks pass, re-fetch/re-check the remote immediately before push, and never force-push.
